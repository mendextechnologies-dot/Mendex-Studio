## 1. Classification Methodology

In compliance with `AGENTS.md`, `docs/architecture.md`, and `docs/engineering-rules.md`, every finding from the independent audit is classified under one of five strict categories:

1. **Software Fix Implemented & Verified:** The defect in software logic, validation, packaging, or interface was remediated with reviewable code changes and proven by positive and negative automated tests against isolated temporary fixtures (`tmp_path`).
2. **Implemented but Not Tested:** Functional code exists but lacks an isolated regression test (zero items in this table remain in this state).
3. **Partially Implemented:** Software handles a subset of the gap; remaining portions require external clarification or tool upstream work.
4. **External Engineering Dependency:** Physical, regulatory, or organizational requirement that cannot be fabricated by software (e.g. physical EMC chamber testing, accredited laboratory calibration, external supply-chain lead-time quotes, human reviewer signing authority).
5. **NOT_EVALUATED:** Unchecked operating envelopes, unmeasured physical values, or unconfigured tools. Missing, stale, corrupted, or unavailable engineering evidence remains `NOT_EVALUATED`.

## 3. Residual External Engineering Boundaries

In strict compliance with `AGENTS.md` and `docs/engineering-rules.md`, software remediation explicitly preserves the following boundaries:
1. **Physical Testing & Calibration:** Software does not operate physical laboratory hardware, power supplies, oscilloscopes, or thermal cameras. Laboratory measurements must be ingested from calibrated physical test instruments with attributable human engineer sign-offs.
2. **Manufacturing Approvals:** No automated system can grant manufacturing approval. Stage 9 (`MANUFACTURING_RELEASE`) requires attributable human engineering review and authorized signatures.
3. **Third-Party Upstream Capabilities:** Tool adapters report discovered binaries honestly without claiming automated execution where not implemented or qualified.
